# /sync : ซิงก์ระหว่างแชท

ใช้ตอนเปิดหลายแชททำงานบน branch เดียวกัน
การพิมพ์ /sync ถือว่าผู้ใช้อนุญาตให้ pull, merge และ push commit ที่มีอยู่

ตัวเลือก (อาจว่าง): $ARGUMENTS

## ขั้นตอน

1. **ดูสถานะ** : `git fetch origin <branch ที่ทำงานอยู่>` แล้วดู
   - commit ใหม่บน GitHub ที่แชทนี้ยังไม่มี (`git log HEAD..origin/<branch>`)
   - commit ของแชทนี้ที่ยังไม่ได้ push
   - ไฟล์ที่ค้าง commit
2. **ไฟล์ค้าง commit**
   - $ARGUMENTS มีคำว่า push : commit งานที่เสร็จแล้วก่อน ไฟล์ที่ยังแก้ไม่เสร็จให้เว้นไว้ และบอกผู้ใช้ว่าเว้นไฟล์ไหน
   - ไม่มีคำว่า push : pull ต่อได้ตามปกติ git จะยอมถ้าไฟล์ค้างไม่ชนกับไฟล์ที่ GitHub เปลี่ยน ถ้า git ปฏิเสธ ให้หยุดแล้วถามผู้ใช้ ห้าม stash หรือ reset เอง
3. **รวมงาน** : `git pull --no-rebase origin <branch>` (merge เท่านั้น ห้าม rebase ห้าม force)
   - ชนกันในเอกสารสถานะ (`docs/RESUME_PROMPT.md`, `docs/USER_BRIEFS.md`) : เก็บรายการของทั้งสองฝั่ง เรียงตามเวลา
   - ชนกันในโค้ด : แก้เองเฉพาะกรณีที่ชัดเจน (เช่น เพิ่มคนละบรรทัด) ถ้าต้องเลือกว่าพฤติกรรมไหนถูก ให้ถามผู้ใช้
   - หลัง merge ที่แตะโค้ด เช็กว่า C# ยังคอมไพล์ผ่านเท่าที่ทำได้ (CLAUDE.md ข้อ 5)
4. **ส่งงานของแชทนี้** : `git push -u origin <branch>` ถ้าล้มเพราะเน็ต ลองใหม่สูงสุด 4 ครั้ง (รอ 2, 4, 8, 16 วินาที) ห้าม force push
5. **อ่านสิ่งที่แชทอื่นเปลี่ยน** : รายการใหม่ใน "สถานะล่าสุด" และตาราง "แชทที่กำลังทำงาน" ของ `docs/RESUME_PROMPT.md` รวมถึงไฟล์โค้ดที่แชทอื่นแก้ซึ่งแชทนี้กำลังจะแตะ
6. **รายงาน 3 ถึง 5 บรรทัด** : ดึงอะไรมา (commit ไหน งานอะไร), ส่งอะไรขึ้นไป, มีชนกันไหมและแก้ยังไง, ไฟล์ไหนที่แชทอื่นกำลังทำอยู่ให้ระวัง
