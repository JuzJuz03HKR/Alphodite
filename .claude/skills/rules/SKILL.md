# /rules : ตรวจโค้ดกับกติกาของโปรเจกต์

ขอบเขตที่ให้ตรวจ (อาจว่าง): $ARGUMENTS

ถ้าว่าง ให้ตรวจ `git diff origin/<branch ที่ทำงานอยู่>` รวมไฟล์ที่ยังไม่ได้ commit
ผู้ใช้สั่งไว้ว่า**กฎไม่ใช่เหตุผลปัดตกไอเดีย** หน้าที่ของคำสั่งนี้คือรายงานให้เห็น แล้วให้ผู้ใช้ตัดสิน

## รายการตรวจ (จาก CLAUDE.md ข้อ 3)

1. อ่านเข้าใจได้ระดับนักศึกษา ท่าที่ยากมีคอมเมนต์ `ADVANCED PART` อธิบาย
2. คอมเมนต์หัวข้อสั้น ค้นง่าย เช่น `//Player QTE` และกฎพิเศษทุกอันมีชื่อตัวพิมพ์ใหญ่ในคอมเมนต์ทุกจุดที่ใช้ (เช่น `// COUNTER`)
3. **ไม่สร้าง string ใน `Draw`** : ไม่มีการต่อ string, `$"..."`, `string.Format`, `.ToString()` ในเส้นทางที่ถูกเรียกจาก Draw ตัวเลขใช้ `NumberText.Get()` ข้อความเตรียมไว้ตอนโหลด
4. ตัวเลขบาลานซ์ทุกตัวอยู่ `Data/BattleRules.cs` ไม่มีเลขลอยในโค้ดกติกา และโค้ดกติกาการต่อสู้ (`Battle/`) ไม่มีโค้ดวาด
5. แก้ตัวเลขใน `BattleRules.cs` : ต้องจดว่า `docs/TACET_Balance.xlsx` ต้องอัปเดต
6. ขาวดำล้วน สีมาจาก `Core/Palette.cs` เท่านั้น (ไม่มี `Color.Red` หรือ `new Color(...)` นอก Palette)
7. ไม่มีภาพที่วาดหรือเจนแทนอาร์ต ภาพที่ยังไม่มีเป็น `ArtSlot` (VFX ที่วาดด้วยโค้ดทำได้ แต่ห้ามวาดตัวละครหรือฉาก)
8. ไม่มีเสียงชั่วคราว ไฟล์เสียงที่ไม่มีให้ข้ามเงียบๆ
9. ไม่สลับลำดับรายการใน `MusicianList` `MotifList` `EnemyList` `EventList` `ConductorList` (เซฟเก็บเป็นลำดับ) เพิ่มต่อท้ายได้
10. ไฟล์ `.cs` ที่แก้คง BOM แบบเดิม บรรทัดเป็น LF
11. หน้าตาไม้บาตองและสัญลักษณ์โน้ตแก้ที่ `Core/Baton.cs` กับ `Core/NoteGlyph.cs` เท่านั้น ไม่เขียนซ้ำในหน้าจอ
12. ชนิดโน้ต 4 แบบที่ล็อกไว้ (ตวัด f/mf/p, ประกาย, FERMATA, TREMOLO) ไม่เพิ่มชนิดใหม่โดยไม่คุยกับผู้ใช้

## รายงาน

- จัดเป็นรายการ `ไฟล์:บรรทัด` ตามด้วยกติกาข้อที่ชน และเหตุผลสั้นๆ เรียงจากเรื่องที่อาจารย์น่าจะเห็นก่อน
- ไม่เจอเลยก็บอกว่าไม่เจอ ห้ามเดา
- ถามผู้ใช้ก่อนแก้ ยกเว้นผู้ใช้สั่ง "แก้เลย" มากับคำสั่ง
