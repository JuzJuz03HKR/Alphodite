# /system : เริ่มงานในแชทใหม่

ผู้ใช้เปิดแชทใหม่บ่อยตอน context ใกล้เต็ม และอาจเปิดหลายแชททำงานพร้อมกัน
คำสั่งนี้ทำให้แชทใหม่รู้ว่างานอยู่ตรงไหน โดยใช้ token ให้น้อยที่สุด

งานที่ผู้ใช้สั่งมากับคำสั่ง (อาจว่าง): $ARGUMENTS

## ขั้นตอน

1. **อ่านเท่าที่จำเป็น** (CLAUDE.md ถูกโหลดมาให้แล้ว ไม่ต้องอ่านซ้ำ)
   - `docs/RESUME_PROMPT.md` : ตาราง "แชทที่กำลังทำงาน" และรายการแรกสุดใต้ "สถานะล่าสุด" (อ่านถึงรายการวันที่ถัดไปก็พอ)
   - `docs/ALPHA7_DESIGN.md` : ข้อ 10 ข้อ 11 และหัวข้อที่เกี่ยวกับงานถัดไปเท่านั้น
   - เอกสารอื่นอ่านเมื่องานต้องใช้
2. **git** : `git fetch origin <branch ที่ทำงานอยู่>` แล้วบอกว่าในเครื่องตามหลัง นำหน้า หรือแยกทางกับ GitHub กี่ commit และมีไฟล์ค้าง commit ไหม
   ถ้าตามหลังและไม่มีไฟล์ค้าง ให้ `git pull --ff-only` เลย
3. **เครื่องมือ** : นับ skill ใน `.claude/skills/` (ควรมี 30 ตัว : ภายนอก 24 + คำสั่งของโปรเจกต์ 6) และเช็กว่ามีเครื่องมือของ Context7 (ค้นด้วย ToolSearch คำว่า context7) อันไหนหายให้บอกตรงๆ
4. **เปิดโหมด caveman** ตาม CLAUDE.md หัวข้อ 0
5. **จองงาน** (ทำเฉพาะเมื่อ $ARGUMENTS มีงาน) : ดูตาราง "แชทที่กำลังทำงาน" ว่าไฟล์ไม่ชนกับแชทอื่น
   - ชน : บอกผู้ใช้ก่อน ยังไม่เริ่ม
   - ไม่ชน : เพิ่มแถว (วันเวลา, งาน, ไฟล์ที่จะแตะ) แล้ว commit และ push เฉพาะไฟล์นี้ การพิมพ์ /system พร้อมงานถือว่าผู้ใช้อนุญาตให้ push แถวจองนี้
6. **สรุปภาษาไทย 3 ถึง 6 บรรทัด** : branch และสถานะ git, เครื่องมือครบไหม, งานค้างและงานถัดไปจากสถานะล่าสุด, แชทอื่นกำลังทำอะไร
   - มีงานใน $ARGUMENTS : เริ่มทำได้เลย
   - ยังมีคำถามที่ผู้ใช้ต้องตัดสินก่อน (เช่น ALPHA7_DESIGN ข้อ 11) : ถามก่อนเขียนโค้ด
   - ไม่มีงานสั่งมา : เสนองานถัดไปแล้วรอผู้ใช้สั่ง

ห้ามแก้โค้ดในขั้นตอนนี้ ยกเว้นผู้ใช้สั่งงานมาใน $ARGUMENTS
