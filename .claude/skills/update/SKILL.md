# /update : บันทึกก่อนย้ายแชท

การพิมพ์ /update ถือว่าผู้ใช้สั่ง commit และ push แล้ว

หมายเหตุจากผู้ใช้ (อาจว่าง): $ARGUMENTS

## ขั้นตอน

1. **ดึงงานของแชทอื่นก่อน** : `git fetch origin <branch ที่ทำงานอยู่>`
   ถ้า GitHub มี commit ใหม่ ให้ `git pull --no-rebase origin <branch>` ก่อนแก้เอกสาร จะได้ไม่ทับงานกัน
2. **ทวนว่าแชทนี้ทำอะไรไป** : `git status`, `git log origin/<branch>..HEAD`, `git diff` และข้อความในแชท
3. **อัปเดตเอกสาร** แก้เฉพาะส่วนที่เปลี่ยนจริง
   - `docs/USER_BRIEFS.md` : ข้อความยาวหรือสำคัญของผู้ใช้ และคำตอบคำถามแบบตัวเลือก ต้องเป็น**คำต่อคำ**
     ถ้าข้อความหายไปเพราะ compact ให้ค้นใน transcript `.jsonl` ของเซสชัน ห้ามเรียบเรียงใหม่แล้วเขียนว่าคำต่อคำ
   - `docs/RESUME_PROMPT.md` : เพิ่มรายการใหม่บนสุดใต้ "สถานะล่าสุด" ขึ้นต้นด้วยวันที่และหัวข้องาน
     บอก ✅ ที่เสร็จ, ⚠️ ที่ค้างหรือยังไม่ได้ทดสอบ, การตัดสินใจใหม่, **งานถัดไปแบบระบุไฟล์หรือฟังก์ชัน** และหมายเหตุจาก $ARGUMENTS
     ลบแถวของแชทนี้ออกจากตาราง "แชทที่กำลังทำงาน"
   - `CLAUDE.md` หัวข้อ 0 : เฉพาะเมื่อมีกติกาหรือการตัดสินใจใหม่ เขียนสั้นๆ
   - `docs/ALPHA7_DESIGN.md` ถ้าการออกแบบเปลี่ยน, `docs/HANDOFF.md` ถ้าโครงโค้ดเปลี่ยน
   - แก้ตัวเลขใน `Data/BattleRules.cs` : จดไว้ว่า `docs/TACET_Balance.xlsx` ต้องอัปเดตตาม
4. **ตรวจ encoding** : คง BOM เดิมของไฟล์ที่แก้ และบรรทัดเป็น LF
5. **commit และ push**
   - commit ทุกอย่างที่เป็นงานของแชทนี้ ข้อความบอกว่าเปลี่ยนอะไร ใส่ attribution ตามที่ระบบของเซสชันกำหนด ห้ามใส่ชื่อโมเดล
   - `git push -u origin <branch>` ถ้าล้มเพราะเน็ต ลองใหม่สูงสุด 4 ครั้ง (รอ 2, 4, 8, 16 วินาที)
   - ถ้าถูกปฏิเสธเพราะ GitHub มี commit ใหม่ ให้ `git pull --no-rebase` แล้ว push อีกครั้ง ห้าม force push
6. **รายงานสั้นๆ** : บันทึกอะไรไว้ที่ไหน, hash ของ commit, งานถัดไปคืออะไร แล้วบอกผู้ใช้ว่า "เปิดแชทใหม่แล้วพิมพ์ /system"
