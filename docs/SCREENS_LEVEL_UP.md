## 3. ทิศทางที่เลือก : แบบผสม

### 3.1 โครง (ตามหน้าต่อสู้)
- ทุกหน้าคือที่หนึ่งในโรงละครที่ TACET กำลังกลืน ฉากมืด แสงสปอตลงบนสิ่งที่สำคัญ
- หลุมดำของ TACET อยู่ในฉากเสมอ และระยะของหลุมช่วยเล่าเรื่อง (ข้อ 4.3)
- ขาว ดำ เทา แบบ dramatic สีเดี่ยวมีเฉพาะสิ่งที่เป็นของตัวละคร
- หัวข้อ serif ตัวใหญ่ ตัวเล็กเป็น sans เว้นช่องไฟ แบบที่ใช้อยู่

### 3.2 ความจัดจ้าน (แบบ Persona 5, ZZZ, Limbus)
- ตอนเปลี่ยนหน้า : แผ่นดำขาวตัดเฉียงหลายชั้น ตัวหนังสือใหญ่วิ่งผ่าน
- ตอนเลือก : แถบเฉียงพุ่งเข้ามารองสิ่งที่เลือก ตัวหนังสือขยายและเอียงนิดหน่อย มีเงาซ้อน ภาพตัวละครทะลุกรอบ
- ตอนกด : เด้ง แวบ แผ่นเฉียงปิด

   - ปุ่มคำสั่ง (CONTINUE CURTAIN CALL BACK NEXT) : สี่เหลี่ยมเอียงแบบเดิม ตอนปกติพื้นเข้มขอบบางสว่างแบบแคปซูลของ menu7 กล่องคีย์เป็นกล่องเล็กสว่างตัวหนังสือเข้ม ชี้แล้วพื้นกลายเป็นขาว ขอบด้านหน้าขาดเป็นหมึก มีเงาเทาซ้อน กดแล้วเหมือนรายการเมนู
   - ตัวเลือกที่มีภาพ (เลือกวาทยากร เลือกยุค ทำรอบ 2) : แถบสูงเอียงขนานกัน แต่ละแถบตัดภาพของตัวเลือกมาเป็นชิ้น เลขใหญ่เส้นบางกับชื่อ ชี้แล้วแถบไล่สีเดี่ยวของตัวละครนั้นขึ้นจากก้น (menu6)
   - ตัวเลข : เลขสำคัญตัวใหญ่สีเน้น ป้ายตัวเล็กห่าง และแถบความคืบหน้าเส้นบาง (menu7) ใช้กับ Result (เลือดที่ได้คืน Shards) และหน้าอื่นที่มีตัวเลข
2. หัวข้อตั้ง (menu1) : ชื่อหน้าตัวใหญ่หมุน 90 องศาบนแถบแนวตั้งข้างเมนู ใช้กับ Pause Settings Archive
3. ลายเส้นวงกลม (menu3) : เส้นขาวบาง 1 ถึง 2 px มีวงกลมกลวงและจุดบนเส้น ใช้เป็นเส้นคั่น ขอบกรอบ มุมการ์ด เข้ากับวงแหวน QTE และหลุม TACET ที่มีอยู่แล้ว (ต่อยอด `Core/Ornament.cs`)
4. วงแหวนกวาด (menu4, **ผู้ใช้เลือกตามแนะนำ**) : วงกลมขยายจากจุดที่กด (หรือจากหลุม TACET) จนเต็มจอใน 0.3 วินาที ขอบเป็นเส้นสว่าง หมอกแสงจางอีก 0.3 วินาที ใช้เฉพาะช่วงสำคัญ (เริ่มรัน เข้าและออกจากการต่อสู้ ชนะ) การเปลี่ยนหน้าปกติยังเป็นแผ่นเฉียง เวลารวมไม่เร็วกว่าตอนนี้ (ครึ่งละ 0.59 วินาที จาก `ScreenManager.FadeSpeed` 1.7)
5. เข้าหน้า (menu4) : สว่างจากดำ 0.3 วินาที แล้วชิ้นส่วนไล่เข้าทีละชิ้น (ข้อ 4.4)
6. ของในฉาก (menu5) : ร้านกับเหตุการณ์วางของที่เลือกได้ไว้ในฉาก ชี้แล้วขอบเรือง กล่องคำพูดมีป้ายชื่อ (ทำรอบ 1)
7. เสาภาพตัวละคร (menu8) : หน้าวงเป็นเสาภาพหน้า pixel ชื่อ serif ต่อด้วยขีดเฉียง การ์ดท่าอยู่ใต้ภาพ ช่องว่างเป็น + (รอระบบใหม่ และรอผู้ใช้เล่าไอเดียแถบการ์ดของวง)
8. Title แบบผสม (menu2 + menu4) : หลุม TACET ฝั่งขวามีวงแหวนเส้นบางวงใหญ่มีขีดรอบล้อมไว้ วงแหวนกว้างจนขอบซ้ายผ่านคอลัมน์เมนู รายการเมนูเกาะอยู่บนเส้นโค้งนั้น (เมนูโคจรรอบความเงียบ)
9. พื้นมีวงแหวนกับเส้นทาง (menu7) : พื้นเวทีแบบมองเฉียงมีวงกลมซ้อนกันเส้นบาง เส้นทางแตกกิ่งเป็นเส้นเรืองกับจุด ใช้กับ Rest (นั่งพักหันหลังแบบ menu7) และรูปแบบแผนที่ของ Route ตอนคุยระบบใหม่
10. หน้ารวมบนวงแหวน (menu2) : Chapter หรือ Route วางจุดหมายไว้บนวงแหวนใหญ่รอบหลุม ตัวละครหันหลังเดินเข้าหาหลุม (กรอบภาพว่างจนกว่าอาร์ตเสร็จ)

### 3.5 ข้อควรระวัง
- ผู้ใช้เคยบอกว่า transition เร็วไป (รอบ 4) แล้วบอกว่าพอดีที่ `ScreenManager.FadeSpeed` 1.7 (รอบ 5) ความจัดจ้านต้องมาจากรูปทรงและการซ้อนชั้น ไม่ใช่ความเร็ว ถ้าภาพอ้างอิงเร็วกว่านี้ให้ถามก่อน

## 4. ชั้นกลาง (ทำครั้งเดียว ทุกหน้าได้ผลพร้อมกัน)

เรียงตามลำดับที่ควรทำ

### 4.1 ฟอนต์ OFL
- ทำภาพเทียบ 3 คู่ก่อน แต่ละคู่มีหัวข้อ serif ตัวเล็ก sans และตัวไทย ใส่ข้อความจริงของเกม (TACET 4'33, CHOOSE YOUR CONDUCTOR, ปุ่ม ตัวเลข) ทำด้วย Python PIL ส่งให้ผู้ใช้เลือก
- โหลด TTF จาก github.com/google/fonts (GitHub ใช้ได้ใน cloud) เปิดดูไฟล์ OFL.txt ทุกตัวก่อนใช้ และเก็บไฟล์ใบอนุญาตไว้ข้างฟอนต์
- ตัวอย่างที่น่าลอง (ยังไม่ได้เช็กใบอนุญาต)
  - serif คล้าย Palatino : Cormorant Garamond, EB Garamond, Noto Serif
  - sans คล้าย Bahnschrift (แบบ DIN) : Barlow, Saira, IBM Plex Sans
  - ตัวไทย : Bai Jamjuree, IBM Plex Sans Thai, Noto Sans Thai, Taviraj
- เลือกแล้ว : ใส่ไฟล์ใน `Tacetno433/Content/Fonts/` ให้ `.spritefont` ทั้ง 4 ไฟล์ชี้ไฟล์ในโปรเจกต์ (ลองยืนยันว่า path แบบ relative ใช้ได้) build ใน cloud จะไม่ต้องสลับฟอนต์อีก ภาพแคปตรงกับเครื่องจริง แล้วแก้ `.claude/skills/build/SKILL.md` ข้อ 3 กับ CLAUDE.md ข้อ 5 ตาม
- ภาษาไทยยังไม่ทำตอนนี้ (SpriteFont วาดทีละตัว สระบนล่างกับวรรณยุกต์อาจวางผิดที่ ต้องหาวิธีตอนทำภาษาไทย) แต่เลือกฟอนต์ที่มีตัวไทยไว้ก่อน จะได้ไม่ต้องเปลี่ยนหน้าตาอีก
- **ผู้ใช้เลือก ข. (28 ต.ค.)** ภาพเทียบทำแบบนี้ : ใส่ฟอนต์ในเกมจริง (สำเนา build ใน cloud) แคป title settings result battle guide reward แล้วตัดมาวางเทียบกับภาพเก่าที่ใช้ฟอนต์ Windows ภาษาไทยทำด้วย Chromium (Playwright) เพราะวางสระและวรรณยุกต์ถูก
  - ก. EB Garamond Medium 500 + Barlow Semi Condensed Medium คู่กับไทย Taviraj + Bai Jamjuree (แนะนำ ใกล้ของเดิมที่สุด อ่านง่ายทุกขนาด)
  - ข. Cormorant Garamond SemiBold 600 + Saira Semi Condensed Medium คู่กับไทย Trirong + Chakra Petch (คมและดราม่ากว่า ตัวเลขแบบโบราณ ตัว 3 ห้อยลง ตัวเล็กบางกว่า)
  - ค. IBM Plex Serif Regular + IBM Plex Sans Condensed Medium คู่กับไทย IBM Plex Sans Thai Looped + IBM Plex Sans Thai (ครอบครัวเดียวกันทั้งไทยและอังกฤษ ทันสมัย ห่างจากของเดิมที่สุด)
- **ทำตอนชั้นกลาง (ชุด ข.)** : ใส่ใน `Tacetno433/Content/Fonts/` พร้อม OFL.txt ของแต่ละตัว
  - `LogoFont` `BigFont` `StoryFont` ใช้ Cormorant Garamond SemiBold 600 (ทำจาก variable ด้วย instancer หรือเอาไฟล์ static จาก github.com/CatharsisFonts/Cormorant) ตอนลองในเกม `StoryFont` 14 px ยังอ่านได้แต่บาง ถ้าเทียบแล้วอ่านยากให้ขยายเป็น 15 ถึง 16 หรือใช้ Bold 700
  - `MainFont` ใช้ `SairaSemiCondensed-Medium.ttf` จาก google/fonts ตามเดิม ห้ามแก้ไฟล์ (มี Reserved Font Name `Saira`)
  - ตัวเลขของ Cormorant เป็นแบบโบราณ (ตัว 3 ห้อยลงใต้เส้น เห็นชัดที่ `4'33`) เป็นหน้าตาที่ผู้ใช้เลือกแล้ว ตัวเลขใน UI ยังเป็น Saira หรือ `PixelDigits`
  - ไทย Trirong (เนื้อเรื่อง) + Chakra Petch (UI) เก็บไว้ใช้ตอนทำภาษาไทย
- ใบอนุญาต : เปิด OFL.txt ของทุกตัวแล้ว เป็น OFL ทั้งหมด ตัวที่มี Reserved Font Name คือ IBM Plex (`Plex`) Lora (`Lora`) Saira Semi Condensed (`Saira`) ใช้ไฟล์เดิมโดยไม่แก้ได้ ถ้าแก้ไฟล์ต้องเปลี่ยนชื่อฟอนต์
- EB Garamond กับ Cormorant Garamond ใน google/fonts เป็น variable font MonoGame อ่านได้แค่น้ำหนักตั้งต้น (EB Garamond 400, Cormorant 300) ต้องทำไฟล์น้ำหนักเดียวก่อน `pip install fonttools` แล้ว `fonttools varLib.instancer "EBGaramond[wght].ttf" wght=500 -o EBGaramond-Medium.ttf` (สองตัวนี้ไม่มี Reserved Font Name ทำได้) หรือเอาไฟล์ static จาก repo ต้นทางของฟอนต์
- ที่โหลด : `https://raw.githubusercontent.com/google/fonts/main/ofl/<ชื่อ>/` ชื่อไฟล์ดูใน `METADATA.pb` ของโฟลเดอร์นั้น (api.github.com ถูกบล็อกใน cloud)

### 4.2 เลนส์เดียวทั้งเกม
- ตอนนี้ `BattleScreen` วาดเองใน PreDraw (SCENE LIGHT GLOW แล้ว `PostChain.Finish`) หน้าอื่นวาดตรง
- ทำให้ `ScreenManager` ใช้ `PostChain` กับทุกหน้า หน้าที่ไม่ได้วาดชั้นเองได้แสงเวทีอัตโนมัติ (แสงรอบตัวจางๆ + สปอตบนสิ่งที่ focus) bloom และ vignette
- LESS FLASHING (`Settings.ReduceFlashing`) ลดแวบทุกหน้า ไม่มี shader (`Fx.Ready` false) ต้องไม่พัง หน้าต่อสู้คงแบบเดิม

### 4.3 TACET แบบเดียว
- ให้ `TacetVoid` วาดหลุมที่ตำแหน่ง ขนาด ความแรง ที่แต่ละหน้ากำหนดได้ แล้วเลิกใช้ `Hollow` กับ `TacetField` ในหน้าที่ยกระดับแล้ว
- ระยะของหลุมเล่าเรื่อง (ไอเดียเริ่มต้น เทียบกับภาพอ้างอิงก่อน)
  - Title : หลุมฝั่งขวา หมุนช้า เมนูอยู่ในแสง
  - Chapter : หลุมกลางจอ ชื่อท่อนโผล่จากขอบหลุม
  - Route : หลุมอยู่ปลายทางตรงบอส ใหญ่ขึ้นทุกห้องที่เดินเข้าใกล้
  - Shop Event : หลุมไกล กระพริบหลังฉาก
  - Rest : ไกลที่สุด แสงนุ่มที่สุด
  - Result ชนะ : รับต่อจาก impact frame ของตีสุดท้าย (พื้นขาวกลับสี) แล้วหลุมแตกเป็นแสง
  - Defeat กับ CurtainCall ตอนแพ้ : ความมืดกลืนจากขอบเข้ามา
  - Settings Pause : หลุมนิ่งจางๆ

### 4.4 ชุด UI กลาง
- `Core/Ui.cs` + ไฟล์ใหม่สำหรับการเคลื่อนไหว (เช่น `Core/UiMotion.cs`) ทุกหน้าเรียกใช้ แก้ที่เดียว
- เข้าจอ : ชิ้นส่วนไล่ทีละชิ้น หน่วงกันนิดหน่อย ค่อยๆ หยุด (ease out)
- hover และเลือก : แถบเฉียงพุ่งเข้ามารอง แสงกวาด ตัวหนังสือขยาย เงาซ้อน
- กด : เด้ง + แวบ
- ตัวเลขนับขึ้นด้วย `PixelDigits` (Result, Shards, ราคา)
- เปลี่ยนหน้า : `Core/SlantWipe.cs` เป็นแผ่นเฉียงหลายชั้นแบบจัดจ้าน แต่ใช้เวลารวมเท่าเดิม

### 4.5 สีตัวละครใน UI

### 4.6 กรอบภาพหน้า pixel แทน chibi

### 4.7 ภาพคมบนจอใหญ่ (งานใหญ่สุด ADVANCED PART) : ทำแล้ว 28 ต.ค. ดูข้อ 11

  - `Sharp.Scale` = real pixel ต่อ game pixel : หน้าต่าง 1 / 1920×1080 = 1.5 / 2560×1440 = 2 / 4K = 3 (สูงสุด `Sharp.MaxScale` 3 จอใหญ่กว่า 4K ยืดภาพ 4K)
  - `Sharp.Dot` = 1 real pixel วัดเป็น game pixel ใช้กับรูปทรงที่วาดเป็นแถว
  - `TacetGame.UpdateView` ตั้งค่าทุกครั้งที่ขนาดหน้าต่างเปลี่ยน (เปิดปิดเต็มจอ) ภาพ `screen` และภาพทุกใบของ `PostChain` สร้างใหม่ตามขนาด
- ตัวหนังสือ : ฟอนต์ทุกตัวมีชุดใหญ่ 3 ขนาด (`Content/*_15x` `*_2x` `*_3x.spritefont` รวม 12 ไฟล์ ไฟล์ฟอนต์ OFL เดิม) เกมโหลดชุดที่เล็กที่สุดที่ยังใหญ่พอกับจอ (`Core/SharpText.cs`) ตัวอักษรจึงถูกย่อลงเท่านั้น ไม่ถูกขยาย
  - ADVANCED PART : ตำแหน่งตัวอักษรยังคิดจากฟอนต์เดิม (สูตรเดียวกับ MonoGame) แค่เอาภาพตัวอักษรจากชุดใหญ่มาวาง จึงตรงกับ MeasureString และข้อความที่ตัดบรรทัดไว้แล้วทุกตัว แต่ละตัววางบนพิกเซลจริงเต็มพิกเซล
- `Core/Gfx.cs` : กล่องวางขอบบนพิกเซลจริง เส้นบาง (ไม่ถึง 1.5 game pixel) หนาเท่ากันทุกที่ เส้นหนาเป็นจำนวนเต็มพิกเซลจริง วงกลม เพชร ลูกศร สามเหลี่ยม capsule pill กล่องเฉียง วาดเป็นแถวสูง 1 พิกเซลจริง (ขอบเนียนตามความละเอียดจอ) เส้นโค้งแบ่งชิ้นละราว 6 พิกเซลจริง glow วางละเอียดระดับพิกเซลจริง
- `PostChain` : BACK SCENE GLOW FINAL ขนาดจอจริง ส่วน LIGHT MAP (640×360) กับ SOFT (320×180) ขนาดเดิมทุกจอ bloom จึงกว้างเท่าที่จูนไว้ ส่วน Down pass อ่าน SCENE กับ GLOW จาก mipmap ระดับที่เท่ากับ 1280×720 (`Post.fx` ค่า `Lod`) glow บนจอใหญ่เลยออกมาเหมือนในหน้าต่างและไม่กะพริบ
- อื่นๆ : `SlantWipe` แถบสูง 2 พิกเซลจริง และกล่องตัดคำ (scissor) คูณขนาด, `Curtain` แถบผ้า 4 พิกเซลจริง, film grain 1 จุดต่อพิกเซลจริง, `PixelDigits` ขอบลงพิกเซลจริง, กล้องฉากต่อสู้ (`Layer`) ขยับทีละพิกเซลจริง, ภาพสุดท้ายวางลงหน้าต่างแบบพิกเซลต่อพิกเซล (PointClamp)
